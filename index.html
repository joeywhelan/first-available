Rules in the tools, not the prompt

A Netomi agent books appliance-repair visits from live AlloyDB search. The rules it must never break are enforced by the database, not by the model.

Netomi Solutions Architecture · Summit Home Services demo

The pattern

A rule in a prompt holds most of the time. A rule in a tool holds every time.

Soft: what needs judgment

Lives in the agent's instructions and tool descriptions.

  • Tone and wording
  • What to refuse
  • When to escalate to a person
  • How to present results

Hard: what must always hold

Lives in SQL functions behind MCP tools, and in database privileges.

  • Who serves which ZIP code and brand
  • Which slots can be offered
  • How a booking is made, and only once
  • What the agent's database user can touch

Architecture

The agent reaches the data through one narrow path

  • 01Netomi Agentic Studio runs the agent: instructions, knowledge, a booking playbook, and three MCP tools.
  • 02An MCP server is the only way in, through one tunnel with a bearer token.
  • 03AlloyDB holds the live data and runs the search, with embeddings from Vertex AI.
  • 04A simulated customer drives each conversation through the Netomi Chat API.

AlloyDB as a search engine

Keyword and vector search, fused in plain SQL

BM25Exact words, error codes and part numbers, such as E24 or KS-PMP-410.
ScaNNMeaning, over embeddings AlloyDB creates itself through Vertex AI. No separate vector store.
HybridReciprocal rank fusion gives one ranking. An exact part number always ranks first.

Take it back to your stack

Find the rules that must never bend. Put them in the tools.

  • 01List the rules that must always hold. Eligibility, availability, limits, anything a wrong answer would cost you.
  • 02Enforce each one in a function behind a narrow tool. Typed arguments, bound parameters, a clear result.
  • 03Give the tools a database account that can only run those functions. No direct access to the tables, so even a fooled agent can't read or change data any other way.
  • 04Leave judgment to the Netomi agent. Understanding the customer, choosing the tool, recovering and escalating.
